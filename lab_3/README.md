# Лабораторна робота №3
Збереження даних через Entity Framework Core. Варіант 2.

## Запуск у Visual Studio
Відкрийте IoTTelemetryLab.slnx, дочекайтеся відновлення NuGet-пакетів та натисніть Ctrl+F5.
Використовуються .NET 8 і EF Core 8.0.11 (Sqlite, Design, Tools).
Пункт 8 створює п'ять сенсорів по 50 сирих показів у діапазоні 0-10 мм/с.
Некоректні покази NaN і -999 вилучаються перед записом.
Пункт 7 показує максимум вібрації для кожної осі X/Y/Z за спаданням.
Повторне наповнення пропускає вже наявні імена сенсорів.

## Загальна частина
1 - створення сенсора; 2 - список; 3 - покази за Id у порядку часу;
4 - перейменування; 5 - каскадне видалення сенсора;
6 - видалення показів за порогом, діапазоном або датою UTC.
Перед видаленням програма показує наслідки та очікує y; інша відповідь скасовує дію.
Порожній результат обробляється повідомленням «Немає даних».

## Міграції
InitialCreate створює Devices і Records зі зв'язком один-до-багатьох.
AddAxisField додає обов'язкове рядкове поле Axis (максимум 20 символів).
Обидві міграції згенеровані інструментом EF Core.
На запуску Database.Migrate() застосовує міграції, якщо це необхідно.
EnsureCreated не використовується.

Для роботи з міграціями вручну відкрийте термінал у папці lab_3:
~~~
dotnet restore IoTTelemetryLab/IoTTelemetryLab.csproj
dotnet tool install dotnet-ef --version 8.0.11 --tool-path .tools
.tools/dotnet-ef migrations list --project IoTTelemetryLab
.tools/dotnet-ef database update --project IoTTelemetryLab
~~~
Якщо інструмент уже встановлений, повторювати install не потрібно.
Наявні міграції повторно створювати не потрібно.
Під час розробки послідовно виконано migrations add InitialCreate та, після додавання Axis, migrations add AddAxisField.

## Файл бази
iot_telemetry.db зберігається поруч із виконуваним файлом у bin/Debug/net8.0.
Шлях виводиться у консолі. Він однаковий при запуску з Visual Studio та dotnet run
для тієї самої конфігурації, тому випадкові окремі бази в робочих папках не створюються.
Після видалення bin база буде створена заново з міграцій; для тривалого збереження
показів перед очищенням збірки слід скопіювати файл бази в резервну папку.
Файли бази, bin, obj, .tools та локальний кеш .packages виключені з Git.

## Структура
Models - Device, TelemetryRecord і незмінна TelemetryReading з ЛР1.
Data - AppDbContext, генератор із ЛР1, DeviceSeeder.
Processing - очищувач із ЛР1 та AxisAnalytics.
Migrations - дві міграції та знімок моделі.
Program.cs - консольне меню, перевірки введення та CRUD.
Індивідуальний запит виконується до context.Records через IQueryable:
GroupBy, Max, OrderByDescending, ToList; без Include та AsNoTracking.

## Перевірки
Перевірено створення бази з обома міграціями, порожню вибірку, максимуми
на контрольних значеннях (Y=9, X=8, Z=5), збереження між запусками, читання,
перейменування, перевірку дублікатів, скасування видалення, видалення показів
за умовою, каскадне видалення та відсутність записів-сиріт.
Контрольні операції виконано на окремій тестовій базі.
